# Регламент командной разработки (Git Flow)

## Ветки
| Ветка | Назначение |
|---|---|
| `main` | Только стабильные релизы, каждый коммит помечается тегом версии |
| `develop` | Интеграционная ветка, в неё вливаются завершённые задачи |
| `feature/<задача>-<кратко>` | Разработка одной задачи, создаётся от `develop` |
| `release/<версия>` | Подготовка релиза, создаётся от `develop`, вливается в `main` и `develop` |
| `hotfix/<кратко>` | Срочное исправление, создаётся от `main` |

## Жизненный цикл задачи
1. Developer создаёт ветку `feature/...` от `develop`.
2. Коммиты оформляются по Conventional Commits: `Feat:`, `Fix:`, `Docs:`, `Chore:`, `Test:`.
3. Developer отправляет ветку и открывает Pull Request в `develop` по шаблону.
4. Tech Lead проводит Code Review по чек-листу.
5. После одобрения и устранения замечаний Pull Request вливается слиянием; ветка задачи удаляется.

## Роли
- Developer — реализует задачу, пишет тесты, отвечает на замечания.
- Tech Lead — проводит Code Review, принимает решение о слиянии, выпускает релизы.
